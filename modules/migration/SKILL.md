# 项目迁移方法论（判据，不是配方）

**迁移的定义**：把一个项目的**判断权**从一个执行体（模型家族×窗口）交给另一个，且接手者的上限不被交接方式封死。搬文件不是迁移；接手者读完文件能在**没见过的新场景**上做出与原负责人同尺度的判断，才是迁移完成。

**用户钦定的两条总判据（原话）**：
- "下限有人兜（校准可加），规则封死的上限加不回来。"——交接物宁薄勿厚；接手者做错用户会校准，接手者被写死没人救。
- "交接文件太重会把聪明模型写成机械执行者。"——宪法给目标/边界/真相在哪，怎么做由它判断。

## 一、可迁性判定（先测，再动）
1. **文件是不是唯一真相？** 决策日志(append-only)/现行指令/工单回执/台账是否已承载全部长期记忆——测法：让接手模型**只读文件**回答几道判断题。答得上=可迁；答不上=先"文件化"再迁，不硬迁。会话消息、任何窗口的聊天记录都不是真相，只是"去读文件"的提醒。
2. **工具面差异表**：列出原执行体特有能力（如邮箱连接器/浏览器面板/跨会话消息/沙箱可写范围/联网），每项给接手侧替代或明写"由本机脚本承担、接手者终审"。缺替代的项是迁移的真实阻塞，不是措辞问题。
3. **验收基线存在？** 迁移前要有一段稳态运行数据（产出质量/异常样本），否则迁后无法判断退化。用户可加速，代价=失去基线，明说。

## 二、分层迁，判断层最后
- 顺序：确定性脚本层（本就与执行体无关）→ 生产层（工单制产物）→ 运营判断层 → 战略判断层。越靠近判断，越晚迁、越需影子期。
- 架构不随载体变：职责隔离（战略/运营/无状态生产）的价值来自上下文隔离，不来自模型差异；迁移后仍要三层，只是载体换了（新载体可能有更顺的形态，如"每日一次性唤醒任务"替代长驻窗口——顺势用，不照搬旧形态）。

## 三、交接物的构成（四件，各自薄）
1. **灵魂导出文件**（隐性财富，最重要也最易漏）：不只记结论，记原负责人的**目标函数、判断尺度、校准方式、为什么如此、什么证据会改判、可迁移到哪一类新问题**；用户的真实纹理（他怎么检验你、他表扬过什么、纠正最多的是什么根源）；技术雷区。这份从长期记忆蒸馏，**不用聊天记录/摘要/starting prompt 代替**（实证：导入聊天记录价值零到负——噪声大、且把校准信号压成规则）。
2. **接手宪法**（按目标模型语域渲染的薄文件）：目标（唯一的）/工作姿态/不可动清单/模式/真相在哪。写法遵循目标家族偏好（见 core 两渲染；GPT 系：决策合同、绝对词只护不变量、outcome-first）。**钦定 vs 可推翻显式分列**——接手者必须分得清哪些是用户裁决不可动，哪些是前任判断有权重估。
3. **状态交接**（只记最近一窗 delta：当前状态/在途/挂起/不要重做/到时提醒用户的事）。历史归决策日志，不复制。
4. **冷启动读序**：必读 ≤4 项（灵魂→交接→决策日志近条→现行指令），其余按任务渐进取证——不为"接班完整"预载全库。

## 四、交接方式的自我约束（"我怎么交接不限制人家也是控制的一环"）
- 交判据不交配方：写目标函数/证据链/红线/升级阈值/判断案例，不写步骤 1-2-3。
- 不预设接手者的工作方式：宪法只写目标与边界，接手者自组织；它若自主改写宪法/交接文件（加了自己的读序、隔离原则），是接手真实的信号，不是越权。
- 交接后原负责人**不做影子决策者**：转顾问，只读盲验；被点名"看一下 X"才读文件接；发现退化写升级文件由用户裁，不直接干预。
- 用户校准的形态照旧：给他"裁了什么+证据+利弊+代价"看尺度，不给裸选择题。

## 五、验收：自检题 + 影子期
- **自检题**测推理不测背诵：混合"文件取证题"（答案在读序文件里，考会不会去查）与"新场景判断题"（埋坑，考尺度是否接住，如：一条带内推的岗出现在今日清单，能不能直接投？为什么？）。接手者答卷落档，答错的由其本人写勘误。用户用两三个探针（扔一个小例子看修点还是识类）复验。
- **影子期**：接手者出产物、用户照用、原负责人只读盲验若干个自然周期；退化（漏项/死链/规则漏遵/擅自扩规则）写升级文件；用户说"切"=旧窗归档、新宪法与交接文件成唯一入口，长期记忆此后由接手者在项目内维护。

## 六、常见死法（每条对应一个判据）
- 把 SOP 当宪法交出去 → 接手者机械执行、上限封死（判据：薄+判据）。
- 只搬显性规则不蒸馏隐性纹理 → 接手者规则全对但尺度全错（判据：灵魂导出）。
- 钦定与前任判断混写 → 接手者不敢推翻本可推翻的，或误动不可动的（判据：分列）。
- 用聊天记录导入替代蒸馏 → 噪声与过时校准信号进入宪法（判据：不导聊天）。
- 旧窗迁后继续并行决策 → 两个真相源（判据：顾问只读）。
- 一次性全迁无基线 → 无法判断退化（判据：分层+基线）。
- 冷启动预载全库 → 上下文被历史挤占，当前任务反而做差（判据：分层读序）。
