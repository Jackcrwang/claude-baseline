# Codex 协作模式

## 一、分工原则（2026-07 实证修订：历史分布≠能力边界）
- **总负责人角色（Claude 承载）**：需求拆解、工单签发、验收组织、仲裁、给用户的汇总投喂——用户只与它沟通，下属单元不得成为第二汇报渠道。
- **两家族都可任生产线或审查线**：指派按任务性质+已有实证（工程/运行时→Codex 实证厚；取证需回原页→Claude 有凭据面；内容创作→双线对照后按数据轮换），例外指派留痕理由。不按家族刻板分工——"谁历史上干得多"不等于"谁只能干这个"。
- **谁产出，另一家族审**（利益回避：审查者与被审产物同家族时回避胜负判定，只审证据链）。
- 用户只做人类独有判断（拍板/品鉴/取舍）；长文本核对类验证一律机器或异模型闭环，不甩给人类。

## 一.5、重项目治理架构（可选启用，小项目勿套）
- **总负责人三层职责**：责任层（全局/优先级/资源/一致性/风险/整合/用户接口——永不委派，但只经落盘工具行使，防"总责名义事事插手"也防空头总责）；判断层（签发/收单/仲裁/规则变更/里程碑终审——亲自时刻清单化，表外介入留痕）；执行层（路由/机检/证据保全/验收循环——默认委派）。
- **分级收单**：常规单由复核代理机械对账（产物齐+账目闭合+引用闭合）即生效，负责人按比率抽验+异常必达；里程碑/规则相关单亲自收。**负责人拖延抽验记欠账，欠账累积冻结新签发**——制度对负责人也要咬得动。
- **全局队列文件**：跨单状态/写集/优先级唯一汇聚点；派发前查重，写集冲突即冻结上报。
- **负责人自校验**：关键判断（规则变更/架构/给用户的重大投喂）生效前过异家族红队；仲裁只凭可实测窄事实，不可窄化的争议连同双方原文+自己的利益声明上报用户；审计报告原文直达用户，负责人只可附回应不可修改。

## 二、派单纪律
1. 任务书驱动：`codex exec` 的 prompt 只指向一份落盘任务书（目标/边界/只读白名单/产出路径/停线点），不塞长指令。
2. **显式指定模型与 effort**（`-m <model> -c model_reasoning_effort=<level>`），禁全默认；最低足够档起步。派单前比对 CLI 版本（`npm view` vs 本地），落后一个 minor 才升级，升级后跑低成本探针。
3. 后台运行必须 `< /dev/null` 关 stdin（否则可能挂死）；启动后 1-2 分钟验证进程 CPU 在涨；跨环境哨兵结论用原生工具复核（如 Windows 下 MSYS `ps` 看不到原生进程）。
4. 执行者停线点：**产出完成未交单**——不自写 PASS、不预建回执；交单结论由派单方组织的验收链产生。
5. 子代理回传五项契约（结论/证据/未知/阻塞/建议）；指定配置与实配验真分列记录，模型自报身份不可信。

## 三、异源审查（质量攸关产物）
- **跨家族盲审优先**：GPT 家族产物→Claude 子代理盲审，Claude 产物→GPT 家族盲审（同家族异模型只是弱去相关，跨家族才是真异源）。
- 盲审员零实现上下文：只给工单+产物+验收标准；禁读实现过程与日志。
- FAIL→修订代理按精确修复项改→窄复审（只验修复项），收敛为止；每轮应抓到新的真缺口，否则停。
- 盲评对照类任务：盲码后以"泄露者视角"全量扫描清洗产物，不能只反查自己记得的词表。

## 四、并行与仓库纪律
- 调研单可并行、实现单默认串行；写集不重叠是并行前提。
- 多单并行期禁 `git add -A`，只定点加自己产出的路径；对在跑工单的文件改动执行者看不到（等回执或杀了重派）。

## 增补(2026-08-02,来源:同上周期复盘,去项目化)
- **能力结论前先查配置**:执行者"做不了 X"时,先分层排查沙箱档位/权限/网络/路径,再谈能力边界——"只有我能做"多半是派单档位保守。取证类可信任务给高权限档,常规实现与审查保持保守档。
- 执行者自写的验证脚本,其输出以派单方**独立复跑**为准;硬编码字面量冒充计算结果(伪断言)是已实证的失败形态,复核时构造反例验证断言真的会叫。
- 审查者与作者不同家族是原则性要求(与能力无关,档位再通也不合并);内容级盲审的封存映射,主持人同样不读直到结果冻结。

## 档位二细则(省主模型额度模式)
- 委托优先序:一切可委托任务(联网调研/实现/审查/长文读写/机械处理)**默认派 Codex**;Codex 不适合或需第二家族独立性时用子模型(如 opus 档);主模型本体不亲自执行可委托的工作。
- 主模型保留的最小面:任务拆解与派单书、必要的判断与裁决、收单质检(抽验而非重做)、向用户汇报。
- 质量不降的实现方式:验收链照跑(只是执行者换人)、委托书照入库、独立复跑抽验照做;若某任务判断密度确需主模型深度介入,**如实向用户说明后再用,不静默升档**。
- 切换协议:用户说"切换档位"即刻生效,回复中复述"当前档位:X";档位状态在跨会话交接文档中显式记录。
