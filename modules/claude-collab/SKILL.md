# Claude 跨家族协作

## 一、启用判据与分工

- 小项目默认关闭。只有产物质量攸关、另一家族的独立视角可能改变结论，且收益覆盖调用与整合成本时，才建议启用；启用前向用户确认一句。
- 两个模型家族都可生产或审查，按任务性质与已有证据分配，不按历史刻板分工。**谁生产，另一家族独立复审**——审查者与作者不同家族是原则性要求（与能力无关，档位再通也不合并）；审查者与被审产物同家族时回避判定，只审证据链。
- Codex 保持单一整合责任：拆解、证据充分性、仲裁、是否改向和最终交付不外包；Claude 子进程的产出一律回流 Codex 整合，不构成对用户的第二汇报渠道。用户只承担拍板、品鉴和风险偏好等人类独有判断；长文本核对、逐条对账类验证走机器或异家族闭环，不上交人类。
- 不调用或提及 Fable 模型。

## 二、调用纪律

1. 用一份落盘任务书驱动调用；任务书只含目标、只读输入白名单、输出要求、验收标准与停线点，不塞实现过程。
2. 显式指定模型：`claude -p --model opus --output-format json`（低风险初筛可按项目证据选择较低档，但不得依赖默认模型）。调用发生在 Codex 沙箱内时需开沙箱联网（`-c sandbox_workspace_write.network_access=true` 或等价配置），否则必然失败；`claude` 复用用户本机登录态，若返回 401 先看是否 token 恰好过期（重跑一次即可判定），不要立刻让用户重新登录（本机实测 2026-08-18：同一命令前后两次一 401 一成功）。工作目录用 ASCII 路径，中文路径会被引号包装吃掉。
3. 工具必须收窄为只读集合。推荐同时限制可见与自动许可工具：`--tools "Read,Glob,Grep" --allowedTools "Read,Glob,Grep"`；确需仓库命令时只增加窄化的只读 `Bash(...)` 模式，不开放 Edit/Write。
4. 后台调用关闭 stdin：POSIX 用 `</dev/null`；PowerShell 启动器显式把标准输入重定向到空设备。启动后记录进程、耗时、退出码、stderr 与原始 JSON，不把“进程启动”当成功。
5. 回传固定五项：结论 / 直接证据 / 未知与置信度 / 阻塞 / 可执行建议。另记录请求模型与返回的实际模型字段；模型自报身份不作证据。
6. 鉴权、网络或权限预检失败即停止该支线并如实降级，不重复调用碰运气；主交付继续用现有证据完成。
7. 被调用方停线点=产出完成未交单：不自写 PASS、不预建回执，结论由 Codex 的验收链产生。被调用方自写的验证脚本，其输出以 Codex 独立复跑为准；硬编码字面量冒充计算结果（伪断言）是已实证的失败形态，复核时构造反例验证断言真的会叫。

## 三、跨家族盲审

- GPT 家族产物交 Claude 审；Claude 产物交 GPT 家族审。盲审员只看工单、冻结产物和验收标准，不读实现日志、作者解释或前轮辩护。
- 审查输出定位可验证缺口，不代替整合者盖章。FAIL 后由修订者处理精确修复项，再做窄复审；连续一轮没有新的真实缺口时停止空转。
- 盲评对照先封存作者映射，冻结结论后再揭盲；主持人也不提前读取映射。
